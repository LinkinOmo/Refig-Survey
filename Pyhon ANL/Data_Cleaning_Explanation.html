Overview of Data Cleaning in Python

This document explains the technical data cleansing operations performed across the Python scripts and analytical Jupyter Notebooks within the Air_Ref_Servey project.

The project employs a dual-layered data cleaning strategy: first addressing raw string encoding corruptions, and then performing rigorous structural data prep using Pandas.

1. Repairing Thai Encoding Corruptions (Mojibake)

Early in the pipeline, exported text and system strings often suffer from Unicode corruption (mojibake) where Thai characters are misrendered (e.g., seeing 'เธฃเธฒเธข...' instead of 'รายงาน').

The Dictionary Mapping Strategy

Standalone Python scripts (like fix_final.py and fix_final2.py) resolve this by scanning the project's source code and output files.

  • Hex/Unicode targeting: The scripts map specific corrupted Unicode sequences back to their correct Thai consonant/vowel counterparts.
  • Length-aware replacement: The script intelligently sorts the mappings by length (longest first) before applying the .replace() function. This ensures that complex compound corrupted words are safely translated before smaller single-character replacements happen, preventing overlapping replacement errors.
# Example from fix_final.py for key in sorted(char_map.keys(), key=len, reverse=True): text = text.replace(key, char_map[key])

2. Structural Data Cleaning via Pandas (Jupyter Notebooks)

Once raw text is legible, the core of the data cleansing happens inside the analytical Python Notebooks (e.g., Refig_Survey_AnalysysR2_fill_recheck.ipynb).

A. Coercing Data Types

Survey inputs and spreadsheet formulas often leave numeric columns contaminated with text (like "N/A" or "Unknown"). Pandas is used to violently coerce these into workable numbers.

  • Numeric Coercion: By using pd.to_numeric(..., errors='coerce'), any stray string data in numeric fields (like Ref Open Qty or kWh 2025) is immediately converted into a safe NaN (Not a Number) value, preventing mathematical crashes.
  • Datetime Coercion: Similar operations are performed on timestamps and Date Open Store columns, using errors='coerce' along with dayfirst=True to standardize the timeline.

B. Imputing Missing Values (Filling)

Machine learning models and aggregate charts cannot process missing blanks (NaN). Depending on the specific context of the data, different imputation strategies are used:

  • Zero-Filling: Missing counts (like the total number of refrigerator units) or missing initial foundation years are safely assumed to be zeros utilizing .fillna(0).
  • Median/Mean-Filling: Missing environmental variables (like Net sqm) are intelligently patched using the median square formatting of similar fleet stores (.fillna(median_sqm)) to preserve the integrity of the data distribution.
  • Categorical Defaults: Missing text columns (like BCM CM Region) are safely defaulted to 'Unknown'.
ref_df['Ref Open Qty Num'] = pd.to_numeric(ref_df['Ref Open Qty'], errors='coerce').fillna(0) uni['Net sqm'] = uni['Net sqm'].fillna(median_sqm)

C. Merging & Truth Validation

The survey data inherently contains human error regarding store hierarchies and reporting regions. The cleaning process standardizes this by relying on a 'Source of Truth'.

  • The scripts heavily rely on merging the raw survey frames with a trusted master_active store catalog using Store ID or GOLD Code as the key.
  • Once merged, user-submitted locations are overwritten or supplemented with verified internal regions (like DD Name (14) and BCM CM Region).
  • Finally, secondary columns like Store Age (yrs) are freshly calculated via Python, overriding any static age values typed into the survey.
