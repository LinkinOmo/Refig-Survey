Git Workflow Manual

A quick reference guide for managing your project code via Git and GitHub, specifically tailored for the Air_Ref_Servey project.

⚠️ CRITICAL RULE: Never push API keys, passwords, or Google Service Account `.json` files to GitHub. Make sure your `.gitignore` file includes the `Service Account/` directory.

1. Initial Setup: Linking to GitHub (HTTPS vs SSH)

Before you can push or pull, your local project folder must be connected to a repository on GitHub. You do this by adding a "remote" origin. There are two primary ways to format this connection link:

Method A: HTTPS (Web Link)

Best for: Quick setup without technical hurdles. When you push, GitHub will periodically prompt you to authenticate via a pop-up web browser window or by using a Personal Access Token.

git remote add origin https://github.com/Username/Repository.git

Method B: SSH (Secure Shell)

Best for: Seamless, long-term workflow. It never asks for a password every time you push. However, it requires a one-time technical setup where you generate an SSH key on your PC and upload it to your GitHub profile settings.

git remote add origin git@github.com:Username/Repository.git

How to check what method you are currently using:

git remote -v

How to change your link method (e.g., swapping from HTTPS to SSH):

git remote set-url origin git@github.com:Username/Repository.git

2. The Standard Workflow (Saving & Pushing)

When you make changes to files or add new ones, follow these three steps in your terminal to safely send them to GitHub:

  • Stage Your Changes: This tells Git which files you want to include in your next save.
    git add .

    Note: The `.` adds all modified and new files in your folder (ignoring whatever is in `.gitignore`).

  • Commit Your Changes: Packages the staged files with a descriptive message.
    git commit -m "Describe what changes you made here"
  • Push to GitHub: Uploads your completed commit to the remote repository.
    git push origin main

3. Getting the Latest Updates

If you or someone else made changes directly on GitHub, you need to pull those updates down to your computer before doing any new work.

git pull origin main

4. Checking Your Status

If you ever get confused about what files have been changed, what is staged, or what branch you are on, use the status command:

git status

5. Handling Sensitive Files

We use a file named .gitignore to tell Git to ignore passwords or secret folders. If you add a new sensitive folder that you do not want on GitHub, you must open .gitignore and type its name before running your first `git add .` command.

If you accidentally added a sensitive file, you can untrack it without deleting it from your computer like this:

git rm -r --cached "Name of Folder or File"

After running that, immediately create a new commit so it saves the removal.
